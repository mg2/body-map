# Architecture
- `src/lib/youtube/url.ts` URL/channel parsing (pure). `api.ts` official API adapter (server-side only; key never logged/returned).
- `src/lib/matching.ts` deterministic matcher (whole-word aliases, plurals, hashtags, sub-phrase suppression). `catalog.ts` muscle catalog. `bodymap.ts` SVG generator; element IDs `muscle-<view>-<slug>` map 1:1 to catalog slugs (tested).
- `src/lib/db.ts` SQLite (`node:sqlite`), versioned migrations. `admin.ts` all mutations (re-entrant transactions). `sync.ts` pipeline: channels.list once → playlistItems.list (paged) → videos.list (batches of 50) → upsert; metadata-only updates for known videos; lock; retries; per-run report. `io.ts` CSV/JSON/backup/restore.
- `src/server.ts` node:http JSON API + static files. Public routes: `/api/muscles`, `/api/map`, `/api/muscles/:slug/videos`, `/api/recent`. Admin routes: `/api/admin/*`. `public/` is a dependency-free client.
- Secrets: `YOUTUBE_API_KEY` is read from `.env.local` by `node --env-file`, held only in server memory; tests assert it is absent from every response, page and export.
- Classification: `classifyUpload` (title only): release phrase + catalog match → auto-mapped (approved); otherwise stored as `ignored` with an `[auto] reason` (the Skipped list). `reclassifySkipped` re-checks only `[auto]` rows. Manual assignment/ignore always wins; sync never touches existing mappings.
- Deviation from the original spec: no Next.js/Prisma/Tailwind/Zod/Vitest (not installable in the build sandbox). Migration path: `db.ts`/`admin.ts` become Prisma queries, `server.ts` routes become route handlers, validation moves to Zod. Extension points: optional AI matcher behind `matchVideo`'s interface (off by default), more SVG shapes in `SHAPES`, more catalog entries.

- Artwork: `src/lib/artmap.ts` maps body-muscles regions (`src/vendor/body-muscles/regions.json`, Apache-2.0) to catalog slugs (`ART`); `bodymap.ts` draws them, with group slugs underneath their children. Muscles the artwork lacks keep schematic shapes (`SHAPES`, authored on a 200x440 canvas as ellipse parameters) that `warpEllipse` places onto the artwork figure and `facet()` draws as pointed, angular polygons to match the artwork's style, clipped to the body outline (`clip-<view>`) using landmark bands measured from region bounding boxes. Element ids (`muscle-<view>-<slug>`), ARIA attributes and state classes are unchanged by the artwork. Tests assert that all 89 regions are mapped or deliberately decorative.

- Collections: each video has a `collection` ("release" | "yoga", schema v2). `src/lib/channels.ts` holds per-channel settings (the original channel keeps its legacy un-prefixed keys, others use `<collection>.<key>`), `sync.ts` loops over configured, enabled channels and isolates failures per channel, and every public query takes a collection filter (`all` by default). Classification is per collection (`classifyFor` in `admin.ts`): release = release phrase + muscle names, yoga = `classifyYoga` (area, pose and muscle rules with sub-phrase suppression and noise stripping). Older backups are migrated on a private copy before restore (`migrate`).
- Front end: "newest request wins" counters on the map, muscle list and detail panel keep a slow earlier response from overwriting a newer collection choice; `#map[data-coll]` records which collection the current drawing belongs to.
- Full body is a catalog entry (`full-body`, a non-muscle region) with no body shape. `bodymap.ts` draws it as a frame `<rect>` plus a labelled tab inside each view's SVG (`FRAME_SLUGS`), and `fitFrame()` in the client re-fits both to the viewport on every zoom/pan (the map zooms by moving the viewBox). Everything else (states, search, counts, videos, sync, classification) treats it like any other target.
- `[hidden]{display:none!important}` is required: `main{display:grid}` otherwise overrides the `hidden` attribute and both tabs show at once. `applyView()` ignores a zero-size map (hidden tab) and `tab()` re-applies it on return.

- GitHub Pages (v0.17): `src/lib/state.ts` loads/saves the database as `state/db.json` (one row per line) into an in-memory SQLite. `src/cli/gh-run.ts` (in the Action) replays `ops/*.json` admin requests against `createServer` and optionally syncs. `src/cli/build-site.ts` saves every GET endpoint as a static file, encrypts `ADMIN_TOKEN` with `ADMIN_PASSWORD` into `admin-key.json`, and adds `public/static-api.js`. That shim makes `api()` read the static files and commit writes via the GitHub Contents API. It then polls `api/meta.json` (`doneOps`) until the Action has applied them. `app.js` changes are guarded by `window.StaticApi`, so the local server behaves exactly as before.
